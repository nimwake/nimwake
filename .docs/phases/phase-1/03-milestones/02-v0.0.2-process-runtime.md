## 목표

`FakeRuntime`을 실제 OS process로 교체한다.

lifecycle semantics는 `v0.0.1`에서 확정한 것과 동일해야 한다.
Runtime adapter가 바뀌어도 state machine은 바뀌지 않는다는 것이 이 마일스톤의 증명 대상이다.

**구현 전에 `Child` 소유권 구조를 확정해야 한다.**

---

## 구현 항목

### Process 소유권

- `ProcessController`가 `tokio::process::Child`를 유일하게 소유 → [PRD §70](../../../prd/02-architecture/04-runtime.md)
- 외부 노출은 `ProcessHandle { id, control }`만
- `AppManager`는 `Child`를 직접 보유하지 않음

### 기동과 종료

- `ProcessRuntime` → [PRD §19](../../../prd/02-architecture/04-runtime.md)
- process spawn (`tokio::process`)
- TCP readiness (retry 약 50ms) → [PRD §22](../../../prd/02-architecture/05-manifest-and-readiness.md)
- startup timeout → `startup_timeout_seconds`
- graceful SIGTERM → shutdown timeout → SIGKILL → [PRD §30](../../../prd/02-architecture/07-scale-to-zero.md)
- 신호는 process group 단위로 전달

### 감시와 복구

- `ProcessExited { process_id, status }` 보고 → [PRD §32](../../../prd/02-architecture/08-failure-handling.md)
- `process_id` 불일치 event 무시 → [Invariant 8](../../../prd/02-architecture/02-lifecycle-invariants.md)
- readiness 성공과 process exit의 경쟁 처리 → [PRD §22](../../../prd/02-architecture/05-manifest-and-readiness.md)
- FAILED 이후 재시작 → [PRD §33](../../../prd/02-architecture/08-failure-handling.md)

### 수명과 출력

- daemon–child lifetime: 전용 process group + daemon 종료 시 group 정리 → [PRD §71](../../../prd/02-architecture/08-failure-handling.md)
- stdout/stderr는 **inherit 또는 drain** — 방치된 pipe 금지 → [PRD §19](../../../prd/02-architecture/04-runtime.md)
- working directory / environment 분리 → [PRD §20](../../../prd/02-architecture/04-runtime.md)

## 테스트 fixture

```text
crates/nimwake-fixtures/src/bin/

├── echo-server         정상 동작
├── slow-start-server   readiness 지연 / startup timeout 재현
├── crash-server        기동 직후 비정상 종료 (bind하지 않음)
├── noisy-server        stdout 대량 출력
├── stubborn-server     SIGTERM 무시 → SIGKILL 경로 재현
├── exit-after-server   readiness 이후 사망 → RUNNING에서 FAILED로
└── group-server        손자 process 생성 → process group 정리 검증
```

소형 Rust fixture로 시작한다.

계획에 없던 셋(`stubborn` / `exit-after` / `group`)은 완료 조건이 요구하는데
원래 fixture 목록으로는 재현할 수 없어서 추가했다.

fixture를 **별도 패키지**로 둔 이유는 `CARGO_BIN_EXE_<name>`이 같은 패키지의 bin만 노출하기 때문이다.
통합 테스트도 같은 패키지 안에 있다. `nimwake-core`에 `[[bin]]`을 붙여 library crate를 오염시키지 않는다.

## 완료 조건

- [x] spawn → readiness → stop 전 구간이 실제 process로 동작
- [x] `Child`를 소유하는 코드 경로가 `ProcessController` 하나뿐
- [x] startup timeout 시 `FAILED`로 전이
- [x] SIGTERM 실패 시 shutdown timeout 후 SIGKILL 수행
- [x] RUNNING 중 process가 죽으면 `FAILED`로 전이
- [x] 교체된 process의 `ProcessExited`가 현재 state를 변경하지 않음 — `manager_tests.rs`의 stale event 테스트. 판정 로직은 `AppManager`에 있고 runtime과 무관하므로 `FakeRuntime`으로 결정적으로 검증한다
- [x] readiness 성공과 exit가 동시에 와도 최종 상태가 결정적 — `ProcessRuntime::start`의 `select!`가 `biased`로 종료를 먼저 본다. 죽은 process가 readiness를 만족시킬 수는 없으므로 종료가 이긴다
- [x] `FAILED` 상태에서 새 `acquire`로 재시작 성공
- [x] `noisy-server`가 stdout을 대량 출력해도 멈추지 않음
- [x] daemon 정상 종료 후 managed child 잔존 0
- [x] 반복 실행 후 orphan / zombie process 0

## 구현 결과

```text
crates/nimwake-core/src/runtime/
├── handle.rs                 ProcessControl trait, ProcessHandle { id, control }
└── process/
    ├── mod.rs                ProcessRuntime — spawn + TCP readiness + 조기 종료 경쟁
    ├── controller.rs         Child의 유일한 소유자, SIGTERM→timeout→SIGKILL, stdout/stderr drain
    └── signal.rs             killpg wrapper (nix)

crates/nimwake-fixtures/       fixture 7종 + 통합 테스트 15개
```

`ProcessRuntime`은 **Unix 전용**(`#[cfg(unix)]`)이다. → [PRD §19](../../../prd/02-architecture/04-runtime.md)
Windows에서도 workspace 전체가 빌드·테스트되지만 process 계열 테스트는 컴파일되지 않는다.

`unsafe_code = "forbid"`를 유지하기 위해 `killpg`는 `nix`의 안전한 wrapper로만 호출한다.
`libc`를 직접 부르면 workspace lint를 풀어야 한다.

테스트 54개 통과 (unit 30 / concurrency 3 / lifecycle 6 / process runtime 10 / process lifecycle 5).
`ci.yml`에 `tokio::process` import를 `controller.rs` 밖에서 금지하는 guard를 추가했다.
Invariant 9 guard와 같은 이유다 — 소유권 규칙을 리뷰가 아니라 기계가 지킨다.

구현 중 확정한 세부 결정은 [05. 설계 결정 기록](../05-design-decisions.md)의 D20~D23 참고.
