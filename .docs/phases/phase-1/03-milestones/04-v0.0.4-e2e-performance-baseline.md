## Performance

### 계측 도입

- `RequestTrace` / `StartupTrace` → [PRD §72](../../../prd/03-delivery/05-instrumentation.md)
- 파생 지표: `actor_queue_latency`, `spawn_latency`, `readiness_latency`, `proxy_connect_latency`, `time_to_first_byte`
- 게이지: `active_requests`, `pending_requests`, `daemon_cpu`, `daemon_rss`, `open_fds`, `running_apps`
- 구현 수준은 `tracing` + benchmark mode. 상시 metrics framework는 도입하지 않는다.

### 측정 항목

| 측정                   | 내용                                                        | 근거                                                    |
| ---------------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| direct-backend baseline | Nimwake를 거치지 않은 latency                               | [§42](../../../prd/03-delivery/03-load-tests.md)         |
| warm proxy benchmark    | `proxy_overhead = nimwake - direct`                          | [§42](../../../prd/03-delivery/03-load-tests.md)         |
| cold-start breakdown    | actor queue / spawn / readiness / proxy connect 구간별 분해 | [§42](../../../prd/03-delivery/03-load-tests.md)         |
| concurrency sweep       | 1 → 10 → 50 → 100 → 250 → 500 → 1000, knee point 탐색       | [§42](../../../prd/03-delivery/03-load-tests.md)         |
| CPU / RSS / FD          | daemon 자원 사용량                                           | [§45](../../../prd/03-delivery/07-performance-baseline.md) |
| benchmark report        | release artifact 형식의 리포트 생성                          | [§73](../../../prd/03-delivery/07-performance-baseline.md) |

### 도구 분리

```text
cargo test
    │
    └── correctness / lifecycle / race

HTTP load tool
    │
    └── traffic / latency / concurrency

CI
    │
    └── orchestration
```

HTTP 부하 생성에는 k6 같은 도구를 사용할 수 있다.
