### 누수 검증

| 항목                 | 기준     |
| -------------------- | -------- |
| orphan process       | 0        |
| zombie process       | 0        |
| unexpected open port | 0        |
| file descriptor 증가 | bounded  |
| RSS 증가             | bounded  |
| spawn / stop count   | 일치     |
| 남아 있는 lease      | 0        |

before / after를 함께 기록한다.

```text
FD before                   9
FD after                    9
RSS before             13.8 MB
RSS after              14.1 MB
```

daemon 정상 종료 후 managed child 잔존 0도 함께 확인한다.
→ [PRD §71](../../../prd/02-architecture/08-failure-handling.md)

## Regression

- previous-release comparison → [PRD §73](../../../prd/03-delivery/07-performance-baseline.md)
- performance regression report
- release workflow

비교 형식:

```text
                    v0.0.4     current      Δ

proxy p95           1.20ms      0.91ms    -24%
daemon RSS          16.8MB      14.2MB    -15%
actor queue p95     0.45ms      0.70ms    +56%  ⚠
cold start          720ms       719ms       ~
```

초기에는 **경고만** 남기고 release를 막지 않는다.
baseline이 충분히 쌓이면 `proxy overhead +30% 이상` 같은 상대 threshold를 도입한다.

regression이 발견되면 profiling으로 내려간다. profiling은 CI 필수 단계가 아니다.

## 완료 조건

- [ ] cold-start storm 통과 (`spawn_count == 1`)
- [ ] sustained warm load에서 error rate 0, RSS/FD 증가 bounded
- [ ] 1000 lifecycle cycles 후 process / fd / RSS / lease 누수 없음
- [ ] daemon 종료 후 managed child 잔존 0
- [ ] performance report artifact가 release마다 생성됨
- [ ] 직전 release 대비 비교표가 리포트에 포함됨
- [ ] regression은 경고로 기록되며 release를 차단하지 않음
- [ ] correctness gate 실패 시 artifact를 publish하지 않음
