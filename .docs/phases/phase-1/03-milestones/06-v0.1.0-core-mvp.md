# v0.1.0 — Core MVP

> **Phase 1 — Core MVP** › 마일스톤 6 / 6
>
> 요구사항 원장: [PRD §65 Core MVP Definition of Done](../../../prd/03-delivery/08-definition-of-done.md)

---

## 의미

`v0.1.0`은 새 기능을 추가하는 마일스톤이 아니다.

> Nimwake의 Scale-to-Zero Core lifecycle이 automated correctness, concurrency, E2E, stress test를 통과한 상태.

수동 테스트에서 동작하는 것은 `v0.1.0`의 근거가 되지 않는다.

---

## 판정

[PRD §65 Definition of Done](../../../prd/03-delivery/08-definition-of-done.md)의 모든 항목을 만족해야 한다.

진행 상황은 [04. 완료 체크리스트](../04-acceptance.md)에서 추적한다.

---

## 명시적 제약

`v0.1.0`이 보장하지 않는 것을 릴리스 노트에 명시한다.

```text
daemon restart 후 기존 application process를 재발견하거나 adopt하지 않는다
WebSocket / SSE / 대용량 스트리밍 업로드는 보장하지 않는다
성능 수치는 baseline이며 SLA가 아니다
crash-loop backoff는 없다
dynamic port allocation은 없다
```

→ [PRD §24](../../../prd/02-architecture/06-gateway-and-requests.md) · [§71](../../../prd/02-architecture/08-failure-handling.md) · [§73](../../../prd/03-delivery/07-performance-baseline.md)

---

## 릴리스 후 처리

`v0.1.0` 태그 이후 다음을 수행한다.

1. Android 실기기 검증 — **CI Linux와 동일한 지표**로 비교 → [PRD §49–§51](../../../prd/04-platform/02-android.md)
2. [Phase 2](../../phase-2/README.md) 착수 판단
3. `v0.0.x` 구간에서 발견된 요구사항 변경을 PRD에 반영
4. 축적된 baseline으로 performance regression threshold 도입 검토

Android 검증은 Core에 Android 전용 코드를 추가하지 않는다는 전제에서 수행한다.
→ [PRD §64 Rule 7](../../../prd/06-conventions/01-development-rules.md)
